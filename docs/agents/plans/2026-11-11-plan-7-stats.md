# Plan 7 — Stats page and session summary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the player see progress. This adds an **End session** button with a summary page, plus a Stats page with totals, time per game, per-game stats with day-based trend lines, and recent sessions.

**Architecture:** Pure aggregation lives in `src/features/stats/aggregate.ts`. `Sparkline.vue` is an inline SVG. The views are `StatsView` (`/stats`) and `SessionSummaryView` (`/session/:id`). The session model gains `cards`, through a real schema migration (v1 → v2).

**Spec:** §7, §1. Ruling: `docs/agents/questions/011`.

## Global Constraints

- Plan 1's constraints and `CLAUDE.md` apply. Branch `feat/stats` from `feat/major`; push when Task 5 is green.
- **Migration:** `SCHEMA_VERSION = 2`. `migrations[2]` adds `cards: 0` to every record in `mt:sessions` and to `mt:session-current` when one is missing. It's idempotent and keeps unknown fields. Corrupt values are left untouched (the stores' guards handle them).
- `SessionRecord.cards: number`. `session.noteCard()` increments it (and opens a session if needed). `decks.recordAnswer` calls it. Card answers never call `noteRound`.
- **End session** appears only on Home, next to the session clock, while a session exists. It calls `endSession()` and navigates to `/session/:id`. An unknown id redirects to `/stats`.
- **Summary page:** date, active time, rounds, flashcard answers, then per game (games with rounds or time this session, plus Major when cards > 0): rounds, time, the game's `summarize(roundsOfThisSession).headline`, and the **level now** for adaptive games (`stats.staircases[id]?.level`). The comparison with the previous finished session reads "+12 min · −3 rounds vs last time" (omitted when there's no previous session).
- **Stats page:** a totals card (active time including the open session, sessions, rounds, flashcard answers, **day streak** = consecutive local days with a session ending today, or yesterday if today has none); time per game (bar list, games + Major, sorted, bars as `width%` of the max); then one section per game (the `summarize().stats` list plus the **trend**); a Major section (cards answered + a link to `/major`); recent sessions (the last 10, newest first, each linking to `/session/:id`).
- **Trend:** one point per **local calendar day** over the last 30 days with data. Adaptive games (any round has a numeric `level`) plot the day's **highest level**; others plot the day's **average accuracy** (%). It is labelled ("Highest level per day" / "Average accuracy per day") and has an aria-label. With fewer than 2 days: "The trend appears after two days of play".
- Home footer: a **Stats** link next to Settings.

## Review Focus

1. **Old saved sessions without `cards`** survive the upgrade and the totals. Pinned in Task 1 (the migration test).
2. **Local-day boundaries** (a session at 23:50 and one at 00:10 are 2 days; the streak survives when today has no session yet). Pinned in Task 2.
3. **Empty data** (no rounds, no sessions) renders sensible empty states, not NaN or `-Infinity`. Pinned in Task 2 and Task 4.
4. **The summary for the session just ended** includes time from the last activity span. Pinned in Task 4.
5. **An unknown `/session/:id`** redirects. Pinned in Task 4.

### Task 2: Aggregation logic
**Files:** `src/features/stats/aggregate.ts` (+ test).
**Produces:** `localDay(ms: number): string` (`YYYY-MM-DD` in local time); `dayStreak(sessionStarts: number[], now: number): number`; `timePerGame(sessions: SessionRecord[]): { id: string; ms: number }[]` (sorted descending, zero entries dropped); `totals(sessions: SessionRecord[], rounds: RoundRecord[]): { activeMs; sessions; rounds; cards }`; `dailyTrend(rounds: RoundRecord[], days = 30): { kind: 'level' | 'accuracy'; points: { day: string; value: number }[] }`; `sessionSummary(session, allRounds, previous: SessionRecord | null): { activeMs; rounds; cards; perGame: { id: string; rounds: RoundRecord[]; ms: number }[]; vsPrevious: { ms: number; rounds: number } | null }`.
- [ ] RED tests: local days around midnight (build times with `new Date(y, m, d, h, min)`); the streak with today empty, then counting yesterday; a gap breaking the streak; an empty list → 0; `timePerGame` sums and sorts; `totals` on empty input → zeros; `dailyTrend` takes the max level per day for adaptive games and the average accuracy ×100 for others, keeps the last N days, and returns empty points for no rounds; `sessionSummary` filters rounds by `sessionId`, combines perGameMs and rounds, and computes the vs-previous diffs.
- [ ] GREEN, then commit `feat(stats): aggregation helpers`.
